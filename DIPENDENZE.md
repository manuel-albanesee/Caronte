# Dipendenze all’avvio di Claude Code

Dopo aver installato il kit nel progetto, avvia Claude Code come al solito, anche tramite Headroom. L’hook `SessionStart` esegue il controllo sulle nuove sessioni e alla ripresa. Recupera le release stabili dai repository ufficiali di ECC e RTK e applica i loro aggiornamenti; per FastSkillRetrieval e Headroom segnala soltanto la nuova versione, perché la loro installazione è lunga o l’eseguibile è in uso. `caronte update`, eseguito nella root del progetto a sessione chiusa, applica il kit dal clone locale e aggiorna tutti e quattro. Una SessionStart riuscita può mostrare il cambio di versione all’utente. Lo stato dell’ultima verifica è in `claude-routing-deps/status.json` nei metadati Git del worktree.

| Componente | Come si aggiorna |
| --- | --- |
| ECC | Il kit include sette profili adattati da ECC 2.2.3, i sorgenti di riferimento e la licenza MIT. All’avvio recupera le nuove revisioni compatibili degli stessi riferimenti. Verifica commit, hash dei blob e formato, poi attiva il gruppo completo. Le regole, i modelli e i tool del kit restano definiti nei profili locali. |
| RTK | L’installer lo rileva e lo installa se manca. All’avvio, se c’è una release compatibile più recente, tenta l’aggiornamento tramite WinGet, Homebrew o Cargo dove l’installazione è riconosciuta. Una copia installata manualmente resta utilizzabile. |
| Claude Code | L’installazione nativa ha il proprio canale di aggiornamento. Le installazioni tramite gestore pacchetti seguono il relativo gestore. |
| Node, Git e Python | Node 22+ esegue il kit, Git scarica i repository delle dipendenze e Python 3.11+ crea l’ambiente di Headroom. |
| ICM | I template e la metodologia sono inclusi nel kit, con licenza e riferimenti propri. Il loro aggiornamento segue le versioni del kit perché deve restare compatibile con manifest e ricevute già creati. |
| Headroom | L’installer riusa una CLI funzionante nel PATH. Se manca, scarica la release 0.44.0 e installa la CLI con il proxy in `.claude/vendor/headroom/.venv/`. Il wrapper avvia il proxy con la sessione. `caronte update` porta il runtime del progetto all’ultima release stabile della stessa major (`headroom-ai[proxy]`, solo wheel) e verifica versione e avvio; una CLI esterna resta al suo gestore. |
| FastSkillRetrieval | L’installer lo scarica dal repository ufficiale a una revisione base fissata e lo installa in `~/.fsr/venv`. Il progetto non pubblica release: `caronte update` segue il ramo predefinito, solo in avanti rispetto alla revisione installata e senza cambio di major, verifica `pyproject.toml` con l’hash Git e l’import del pacchetto, poi registra la revisione in `caronte-fsr-revision` (obbligatorio, richiede Python 3.13: senza di lui l’installazione è incompleta). A ogni avvio di sessione lancia in background `init-index --if-stale`, che ricostruisce `~/.fsr/index/claude` solo se skill, agent o comandi sono cambiati (la prima volta circa 3 minuti). Si disattiva con `CARONTE_FSR_AUTOINDEX=off`. |
| Caveman | Configurazione e aggiornamento indipendenti. |

Il controllo degli aggiornamenti usa HTTPS verso GitHub. In assenza di rete, con API limitata, su cambio di major o se una release ECC rimuove o cambia in modo incompatibile un profilo, rimane in uso la copia valida precedente. Il risultato è registrato nello stato locale. Gli aggiornamenti di RTK dipendono anche dalla disponibilità del pacchetto presso il gestore. Nessuna credenziale GitHub è necessaria per consultare le release pubbliche.

I riferimenti ECC aggiornati si salvano nella cache Git e sono indicati ai profili soltanto quando partono. L’installer configura anche il [plugin ECC completo](GUIDA.md#ecc-completo-e-caronte), che include il catalogo, gli agenti nativi e gli hook. La provenienza dei riferimenti inclusi è in `.claude/routing/ecc/manifest.json`. Per tornare a quei riferimenti, rimuovi il puntatore `ecc-current.json` dalla cache Git. Il successivo avvio tenterà di nuovo l’aggiornamento se disponibile.
